# 真机问答运行手册（2026-11-17）

手机「历史」页问 Fit Agent，答案从本机的训练记录里来。这份手册说明
「两个库是什么、一句话怎么走完全程、要开哪些东西、怎么验、出问题怎么办」。

## 一、先分清两个「库」

| | 知识库 | 云数据库 |
|---|---|---|
| 是什么 | 云盘同步目录里的训练 / 健康记录 markdown | 微信云开发里的一个集合 `fit_agent_config` |
| 装什么 | 每日记录正文（答案的来源） | 只有两个配置值：`baseUrl`、`token` |
| 谁读 | 本机 Fit Agent 进程 | 云函数 `askFit` |
| 什么时候用 | 每次问答，检索出相关记录喂给模型 | 每次云函数收到问题，先读它才知道往哪转 |

一句话：**知识库决定「答案从哪来」，云数据库决定「问答服务在哪、钥匙是什么」**。
两者没有任何数据同步关系——云数据库里没有一个字的训练记录。

## 一·五、同一个输入框：既能问历史，也能排计划（2026-11-17 加）

历史页那个输入框现在两种都能问，靠意图识别分流：

- **问历史**（「上次练腿哪天」「深蹲涨没涨」）→ 原来的检索 / 数值入口，答案来自已有记录。
- **排计划**（「帮我排今天的训练计划」「今天练什么」）→ 走另一条路：
  读今天的健康记录 → 调本机排课引擎算出三档 → **不过模型**，直接把算好的文本返回。

为什么不经过 7B：计划里的重量 / 组次是算出来的，交给模型复述它可能算错；
而且不过模型只要 0.2 秒，彻底避开云函数 55 秒 / 小程序 30 秒的超时线。

排计划这条路的额外依赖（历史问答不需要）：

| 依赖 | 说明 |
|---|---|
| 排课引擎 skill | `~/.workbuddy/skills/training-plan-engine/`，纯 Python 标准库 |
| `checkin.py` / `engine.py` | 从健康记录读当日状态、出三档；路径走环境变量 `FIT_ENGINE_SCRIPTS` 等 |
| 当天健康记录 | `01 每日记录/YYYY-MM-DD-健康记录.md`，缺了会明确报错，不会瞎排 |

输出严格按用户定的规矩：**正常 / 降级 / 试探三档并排**、标出**判档结论 = 引擎默认哪档**、
每动作带热身组 / 组间 / 余力提示。**这版只在对话里给计划，不写练练 App**——
选定档位后再说要不要落到排期（练练无删除接口，重复排要手工先删）。

> 注意：排计划读的是**当天健康记录**，不是索引快照，所以不用重启 Fit Agent；
> 但如果你改了引擎脚本本身，要重启服务才加载新代码。

## 二、问一句话的完整调用链

```
手机 历史页
  → ① 云函数 askFit（只发问题原文 q，不带身份 / 身体数据）
  → ② askFit 读云数据库 fit_agent_config 拿 baseUrl + token
         （环境变量填对了就优先用环境变量）
  → ③ 带 x-fit-token 头 POST 到公网隧道 https://<随机域名>.trycloudflare.com/api/ask
  → ④ Cloudflare 隧道转发到本机 127.0.0.1:3000
  → ⑤ Fit Agent 校验 token（隧道来的必须带，本机网页直连豁免）
  → ⑥ 检索知识库：读 KB_DIRS 目录所有 .md → 分块 → BM25 检索 → 取前 5 条
  → ⑦ 调本机 Ollama（qwen2.5:7b-instruct）生成答案，校验每个 [n] 都有出处
  → ⑧ 答案 + 出处原路返回 → 小程序渲染成答案卡片
```

## 三、知识库是怎么被调用的（最容易踩坑的一节）

- **配置**：仓库根目录 `.env.local` 里的 `KB_DIR` / `KB_DIRS`，指向每日记录的云盘同步目录。
- **读取**：`src/lib/corpus.ts` 用 `readdirSync` / `readFileSync` 读目录里所有 markdown。
- **索引**：`src/lib/retrieve.ts` 建 BM25 索引，缓存在**进程内存**（`globalThis.__kbIndex`）。
- **关键限制**：索引只在**进程启动后第一次请求时**构建，之后一直用内存里的快照。
  `isCurrent()` 只检查 schema / 字段 / 目录是否变了，**不检查文件修改时间**。

> 所以：写完当天的训练记录，**必须重启 Fit Agent 服务**，新问题才查得到新内容。
> 这是「明明写了却说库里没有」的头号原因。

## 四、要开什么东西

一共三层，三个本机进程，缺一不可：

| 层 | 东西 | 要不要手动开 | 说明 |
|---|---|---|---|
| 云 | 云函数 `askFit` + 云数据库配置 | **不用** | 托管在微信云，已部署，一直在线 |
| 模型 | Ollama（`qwen2.5:7b-instruct` + `bge-m3`） | 通常不用 | 开机后一直在；`ollama serve` 可确保它在 |
| 服务 | Fit Agent（`127.0.0.1:3000`） | **要** | 读知识库 + 调模型，索引在它的内存里 |
| 入口 | Cloudflare 隧道 | **要** | 手机的公网入口，转到本机回环地址 |

**「两个后台」就是最后两行**：Fit Agent 服务 + 隧道。Ollama 现在是活的、
云函数和数据库在云端，所以你实际要盯的只有这两个。它们都是会话级进程，
终端关掉或 Mac 重启就停——停了不是坏了，重新起即可。

## 五、启动步骤（两个终端，各占一个标签页）

**终端 A —— Fit Agent 服务**

```bash
cd ~/dev/fitness-agent
./scripts/service.sh start-once
```

看到监听 `127.0.0.1:3000` 就成了。这个命令**占住终端**，关掉等于停服务。
（launchd 自启在这台机器上注册失败过，所以走前台方式最稳。）

**终端 B —— Cloudflare 隧道**

```bash
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:3000
```

终端会打印一个 `https://xxxx-xxxx.xxxx.trycloudflare.com`，**复制备用，终端保持开着**。
不用注册账号；TLS 由 Cloudflare 在隧道层终结，Fit Agent 仍然只听回环地址。

**拿到新 URL 后**：去微信开发者工具 → 云开发 → 数据库 → `fit_agent_config` →
那条记录，把 `baseUrl` 改成新的根地址（不带 `/api/ask`、不带结尾斜杠）。
`token` 不用动。

## 六、验证有没有通（从近到远三步）

**1. 本机服务活着**（应返回 `{"ok":true,"index":{...}}`）：

```bash
curl -s --noproxy '*' http://127.0.0.1:3000/api/ask
```

**2. 公网 + token 能问答**（应返回答案和出处）：

```bash
read -s FIT_AGENT_TOKEN; echo
curl -s --max-time 30 -H "x-fit-token: $FIT_AGENT_TOKEN" \
  -X POST https://<你的隧道域名>/api/ask \
  -H 'content-type: application/json' -d '{"q":"上次练腿是哪天？"}' | head -c 400
```

**3. 云函数通**：开发者工具 → 云开发 → 云函数 → `askFit` → **测试**（云端测试，
不是「本地调试」），入参 `{"q":"上次练腿是哪天？"}`，应返回与第 2 步一致的答案。

- 命令里 `--noproxy '*'` 只用于本机地址：环境里有代理，不给本机地址回的是假的 502。
- token 用 `read -s` 输入，不写进命令、不留在 shell 历史、不发到任何聊天工具。

## 七、日常维护

| 场景 | 要做什么 |
|---|---|
| 写完当天训练记录 | 终端 A `Ctrl-C` 后重跑 `start-once`，刷新索引 |
| 隧道 URL 变了（每次重启必变） | 只改云数据库的 `baseUrl`，不动代码、不重新部署、不重新上传 |
| token 轮换 | `.env.local` + 云数据库 `token` 两处同步改，然后重启服务 |
| 合规检查 | 手机号 / 身份证 / token 不进代码、不进 git；提交守卫会拦 32+ 位裸 hex |

## 八、常见报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 公网 `HTTP 530` Cloudflare Tunnel error | 隧道停了 | 重起终端 B |
| 本机 `HTTP 000` | Fit Agent 停了 | 重起终端 A |
| 云函数返回「鉴权失败」 | token 两处不一致 | 对齐 `.env.local` 与云数据库 `token` |
| 云函数返回「未配置」 | 集合名 / 字段名不对，或值格式不合法 | `baseUrl` 须 http 开头、`token` 须 32+ 位 hex |
| 云函数直接超时 | 执行超时不是 60 秒 | 开发者工具把 `askFit` 超时改成 60 |
| 答「库里没有」但明明写了 | 索引没刷新 | 重启 Fit Agent（见第七节） |
| 本机地址返回 502 | 走了代理 | 加 `--noproxy '*'` |
